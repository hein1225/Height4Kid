# v1.1.0 版本开发计划 —— 数据备份功能升级

## 一、版本目标

将现有的"数据管理"模块升级为完整的"数据管理"体系，在保留本地备份/还原能力的基础上，新增 WebDAV、Nextcloud、百度云三种云端同步方式，实现跨设备数据共享——在手机上记录的数据可以自动同步到平板、电脑等其他设备上，随时随地查看孩子的成长情况。

## 二、设置页面改造

### 2.1 现有结构（改造前）

设置页面目前分为三个区块：
- **主题设置**：粉色主题 / 蓝色主题
- **数据管理**：导出数据 / 导入数据 / 清除所有数据
- **关于**：版本信息、检查更新、GitHub 链接

### 2.2 改造后结构

设置页面调整为四个区块：
- **主题设置**（不变）
- **数据管理**（改造，整合备份还原与云同步）
  - 本地：数据备份（原"导出数据"）
  - 本地：数据还原（原"导入数据"）
  - 云同步：WebDAV
  - 云同步：Nextcloud
  - 云同步：百度云
- **其他**（保留）
  - 清除所有数据
- **关于**（不变）

### 2.3 UI 设计要点

- "数据管理"分类下，使用分组卡片区分"本地"和"云同步"两个子区域
- 每个云同步选项点击后进入独立的配置页面（新页面）
- 已配置的云同步服务显示状态标识（已连接 / 未配置）
- 云同步配置页面包含：服务器地址、账号密码、连接测试、自动同步开关

## 三、功能详细设计

### 3.1 本地数据备份（原"导出数据"）

- 功能逻辑不变，仅更名为"本地：数据备份"
- 图标保持 `Icons.file_upload`
- 备份文件名格式：`height4kid_backup_时间戳.json`

### 3.2 本地数据还原（原"导入数据"）

- 功能逻辑不变，仅更名为"本地：数据还原"
- 图标保持 `Icons.file_download`
- 导入前仍需用户确认覆盖

### 3.2.1 清除所有数据

- 位置：移至"其他"分类下
- 行为：清除所有数据时，**同时清除云同步账号配置信息**（服务器地址、用户名、密码、Token 等）
- 清除前需用户二次确认："确定要清除所有数据吗？此操作将同时清除云同步账号信息，且不可恢复。"

### 3.3 云端数据同步 —— 通用设计

#### 3.3.1 同步策略

**⚠️ 重要：自动同步默认关闭**

为防止用户在新设备首次登录后自动同步空数据覆盖云端数据，自动同步功能默认关闭。用户需手动开启后才会生效。

| 触发时机 | 行为 |
|---------|------|
| 打开 App 时 | 若自动同步已开启，检查云端数据与本地数据的差异，如有差异自动同步 |
| 新增/修改/删除孩子数据时 | 若自动同步已开启，自动将变更上传至云端 |
| 手动触发 | 设置页面提供"上传数据到云端"和"从云端下载数据"按钮 |

#### 3.3.2 首次登录提醒

当用户在新设备上配置云同步账号后（本地无数据或本地数据为空）：
- 弹出提示对话框："检测到这是首次使用云同步，是否从云端下载数据？"
- 提供"下载"和"跳过"两个选项
- 若选择下载，执行从云端读取数据操作

#### 3.3.3 手动同步功能

设置页面云同步区域提供两个手动操作按钮：
- **上传数据到云端**：将当前本地数据上传至云端，覆盖云端数据
- **从云端下载数据**：显示云端最近 3 个版本的备份数据列表，供用户选择下载
  - 列表展示每个版本的同步时间、数据大小
  - 最新版本标记"最新"标签，并高亮显示
  - 用户选择后下载并覆盖本地数据（需确认）

#### 3.3.4 云端数据版本管理

- 云端默认保存 **最近 3 个版本** 的备份数据
- 文件命名格式：`height4kid_sync_v1.json`、`height4kid_sync_v2.json`、`height4kid_sync_v3.json`
- 新上传数据时，自动覆盖最旧的版本（v1），并将 v2→v1、v3→v2、新数据→v3
- 每个版本文件包含 `lastSyncTime` 字段，用于展示同步时间

#### 3.3.5 冲突处理策略

- 采用 **"最后修改时间优先"** 策略：比较本地和云端数据的最后修改时间戳，取较新的版本
- 如果本地和云端在同一条记录上都有修改（时间戳相同精度内无法判断先后），提示用户手动选择
- 同步时生成同步日志，记录每次同步的操作详情

#### 3.3.6 数据格式

- 云端存储格式与本地 JSON 备份格式保持一致
- 在 JSON 中增加 `lastSyncTime` 字段，记录最后同步时间

#### 3.3.7 网络异常处理

- 同步失败时不影响本地正常使用
- 失败后自动重试（最多 3 次，间隔递增：5s、15s、45s）
- 重试仍失败则在设置页面显示同步失败提示，等待用户手动处理

### 3.4 WebDAV 同步

#### 配置项
- 服务器地址（URL）
- 用户名
- 密码
- 远程路径（默认 `/height4kid/`）

#### 技术实现
- 使用 `webdav_client` 包（或 `http` 包手动实现 WebDAV PROPFIND/GET/PUT 请求）
- 支持 HTTPS
- 连接测试：尝试 `PROPFIND` 请求验证配置是否正确

#### 同步流程
1. `PROPFIND` 检查远程文件是否存在及最后修改时间
2. `GET` 下载远程文件（如存在）
3. 比较本地与远程数据的 `lastSyncTime`
4. `PUT` 上传较新的数据到远程

---

### 3.5 Nextcloud 同步

#### 配置项
- Nextcloud 服务器地址
- 用户名
- 密码（或 App 专用密码）
- 远程路径（默认 `/Apps/Height4Kid/`）

#### 技术实现
- Nextcloud 底层基于 WebDAV 协议，可复用 WebDAV 同步的核心逻辑
- 额外封装 Nextcloud 专用的配置界面和连接测试
- 支持 Nextcloud 的 App 密码认证方式

#### 同步流程
与 WebDAV 相同，复用 WebDAV 同步引擎

---

### 3.6 百度云同步

#### 配置项
- 百度网盘授权（OAuth 2.0）
- 远程目录（默认 `/apps/Height4Kid/`）

#### 技术实现
- 使用百度网盘开放平台 API（PCS API）
- OAuth 2.0 授权流程：打开浏览器 → 用户登录授权 → 获取 access_token → 存储 token
- Token 自动刷新机制
- 文件操作：`upload`（上传）、`download`（下载）、`meta`（获取文件信息）

#### 同步流程
1. 通过 `filemeta` API 检查远程文件是否存在及修改时间
2. `download` 下载远程文件（如存在）
3. 比较本地与远程数据的 `lastSyncTime`
4. `upload` 上传较新的数据到远程

#### 注意事项
- 百度网盘 API 有调用频率限制，需做好节流
- access_token 有效期 30 天，需实现自动刷新
- 需在百度开放平台注册应用获取 API Key

## 八、风险与注意事项

1. **百度云 API 审核**：需要在百度开放平台注册开发者账号并创建应用，审核周期不确定
2. **Web 端限制**：Web 端的文件系统访问受限，本地备份/还原功能需确保在 Web 端正常工作
3. **数据安全**：云同步涉及传输敏感数据（孩子信息），所有通信必须使用 HTTPS
4. **多端同时修改**：当前版本暂不考虑实时多人协作，仅支持"最后修改时间优先"的简单策略
5. **向后兼容**：本地 JSON 备份格式需保持与 v1.0.x 兼容，新增字段使用可选类型
